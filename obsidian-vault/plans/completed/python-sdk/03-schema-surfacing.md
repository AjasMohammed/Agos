# Phase 3 — Schema Surfacing in Kernel

> Extend `ScriptAnnotations`, `ScriptParser`, `ToolRunner`, and `ScriptWatcher`
> so that the JSON Schema generated by the Python SDK is stored and surfaced
> to the LLM in the agent's system prompt.

---

## Why this phase

Without this phase, Python SDK tools show up in the LLM context with only a
free-text description — the LLM has to guess argument names and types.

With `@schema:`, the ScriptParser extracts a full JSON Schema, the ToolRunner
stores it alongside the dynamic tool registration, and the system prompt
generator can expose it just like a built-in tool's schema.

---

## Current → Target state

| Before | After |
|--------|-------|
| `ScriptAnnotations` has no schema field | `ScriptAnnotations.schema: Option<serde_json::Value>` |
| `@schema:` annotation silently ignored | Parsed as compact JSON, stored in annotations |
| `ToolRunner.dynamic_tools` has no schema side-channel | `ToolRunner.dynamic_schemas: RwLock<HashMap<String, Value>>` |
| `register_dynamic()` takes only a tool | `register_dynamic_with_schema(tool, schema)` also stores schema |
| `unregister_dynamic()` only removes tool | Also removes schema entry |
| No way to retrieve dynamic tool schema | `schema_for(name) -> Option<Value>` |
| ScriptWatcher ignores annotations.schema | Calls `register_dynamic_with_schema` when schema present |

## Detailed subtasks

### 1. `ScriptAnnotations` — add `schema` field

```rust
pub struct ScriptAnnotations {
    // ... existing fields ...
    /// Full JSON Schema from `@schema:` annotation (generated by Python SDK).
    pub schema: Option<serde_json::Value>,
}
```

Initialize `let mut schema: Option<serde_json::Value> = None;` in `extract_annotations`.

### 2. `ScriptParser` — parse `@schema:` annotation

In the annotation scan loop:
```rust
} else if let Some(v) = rest.strip_prefix("@schema:").map(str::trim) {
    if let Ok(parsed) = serde_json::from_str::<serde_json::Value>(v) {
        schema = Some(parsed);
    }
    // Silently ignore parse errors — graceful degradation
}
```

### 3. `ToolRunner` — add `dynamic_schemas` field

```rust
pub struct ToolRunner {
    // ...
    dynamic_schemas: std::sync::RwLock<HashMap<String, serde_json::Value>>,
}
```

Initialize in ALL three constructors (`new_with_model_cache_dir`, `new_with_shared_memory`).

### 4. `ToolRunner` — add `register_dynamic_with_schema`

```rust
pub fn register_dynamic_with_schema(
    &self,
    tool: Box<dyn AgentTool>,
    schema: serde_json::Value,
) {
    let name = tool.name().to_string();
    self.dynamic_tools.write()....insert(name.clone(), Arc::from(tool));
    self.dynamic_schemas.write()....insert(name, schema);
}
```

### 5. `ToolRunner` — update `unregister_dynamic`

Remove schema entry first, then remove tool:
```rust
pub fn unregister_dynamic(&self, name: &str) -> bool {
    self.dynamic_schemas.write()....remove(name);
    self.dynamic_tools.write()....remove(name).is_some()
}
```

### 6. `ToolRunner` — add `schema_for`

```rust
pub fn schema_for(&self, name: &str) -> Option<serde_json::Value> {
    self.dynamic_schemas.read()....get(name).cloned()
}
```

### 7. `ScriptWatcher::try_register` — use `register_dynamic_with_schema`

```rust
let schema = annotations.schema.clone();
match ScriptTool::new(path.to_path_buf(), annotations) {
    Ok(tool) => {
        if let Some(s) = schema {
            tool_runner.register_dynamic_with_schema(Box::new(tool), s);
        } else {
            tool_runner.register_dynamic(Box::new(tool));
        }
        // ...
    }
}
```
