# Phase 2 — CLI Integration

> Extend `agentos tool install` to accept `.py` files. The CLI runs
> `python3 file.py --agentos-manifest`, generates a wrapper script, and writes
> it to `$data_dir/scripts/` where the ScriptWatcher picks it up automatically.

---

## Why this phase

The ScriptWatcher already hot-reloads scripts from the `scripts/` directory.
What's missing is the install pathway: given a user's `my_tool.py`, produce a
wrapper script with all `@agentos` annotations that ScriptParser can read.

---

## Current → Target state

| Before | After |
|--------|-------|
| `agentos tool install <path>` only handles `.toml` manifests | Also handles `.py` files (offline, no kernel needed) |
| No way to install Python SDK tools from CLI | `agentos tool install stock_price.py` just works |

## Architecture

```
agentos tool install my_tool.py
    ↓
cmd_install_py("my_tool.py")
    ↓
python3 my_tool.py --agentos-manifest
    ↓ stdout: {"name":"my-tool","fn_name":"my_tool","input_schema":{...},...}
    ↓
Rust generates wrapper content (inline, no Python needed for this step)
    ↓
write $data_dir/scripts/my-tool.py
    ↓
ScriptWatcher inotify fires → ScriptParser reads @schema: → ToolRunner.register_dynamic_with_schema
    ↓
Agent sees tool with full JSON Schema in system prompt
```

## Detailed subtasks

### 1. Update `is_offline`

```rust
pub fn is_offline(cmd: &ToolCommands) -> bool {
    match cmd {
        ToolCommands::Install { path } if path.ends_with(".py") => true,
        ToolCommands::Keygen { .. } | ... => true,
        _ => false,
    }
}
```

### 2. Add `.py` case in `handle_offline`

```rust
ToolCommands::Install { path } if path.ends_with(".py") => {
    cmd_install_py(&path)?;
}
```

This must appear **before** the existing `ToolCommands::Keygen` arm.

### 3. Implement `cmd_install_py`

Steps:
1. `canonicalize(path)` → absolute path
2. Find Python: try `python3`, fallback `python`
3. Run `python <abs_path> --agentos-manifest` → capture stdout
4. Parse JSON → `serde_json::Value`
5. Extract `name`, `fn_name`, `description`, `version`, `permissions`, `input_schema`
6. Call `validate_tool_name(name)` — reuse existing function
7. Resolve scripts dir: `$AGENTOS_DATA_DIR/scripts` (default `/tmp/agentos/data/scripts`)
8. Build wrapper content string (all inline — no Python subprocess needed)
9. Write to `scripts_dir/<name>.py`
10. `chmod 755`
11. Print success with source path and wrapper path

Wrapper content format:
```
#!/usr/bin/env python3
# @agentos tool: {name}
# @description: {description}
# @version: {version}
# @permissions: {permissions_csv}
# @schema: {compact_json_schema}
# Generated by `agentos tool install` — do not edit manually.
import sys
sys.path.insert(0, {json_encoded_source_dir})
from {source_stem} import {fn_name}
{fn_name}.run()
```

**Security note**: `source_dir_repr` must be `serde_json::to_string(&source_dir)` — not
raw string interpolation — to prevent injection through paths with special characters.

### 4. Create `sdk/python/agentos/generator.py`

Mirror the wrapper generation in Python for use in tests and programmatic workflows:

```python
def generate_wrapper(manifest, source_path) -> str: ...
def write_wrapper(manifest, source_path, scripts_dir) -> Path: ...
```

## Verification

```bash
# Create a minimal test tool
cat > /tmp/test_tool.py << 'EOF'
import agentos

@agentos.tool(name="test-tool", description="A test tool")
def test_tool(x: str) -> dict:
    return {"echo": x}

if __name__ == "__main__":
    test_tool.run()
EOF

# Install it
agentos tool install /tmp/test_tool.py

# Check the wrapper was created
ls -la /tmp/agentos/data/scripts/test-tool.py
head -8 /tmp/agentos/data/scripts/test-tool.py
```

Expected output:
```
#!/usr/bin/env python3
# @agentos tool: test-tool
# @description: A test tool
# @version: 1.0.0
# @permissions: fs.data:r
# @schema: {"type":"object","properties":{"x":{"type":"string"}},"required":["x"]}
# Generated by `agentos tool install` — do not edit manually.
import sys
```
